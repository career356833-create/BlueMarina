# Blue Marina Production Operations & Observability V1

The implementation provides a read-only, fail-closed `/admin/operations` page and `/api/operations/health` endpoint. **Current decision: `OPERATIONS_OBSERVABILITY_V1_BLOCKED` for operator use.** Production has no Supabase Auth URL/public key or verified `operations_admin` actor, so the private page must remain unavailable. No public fallback, fake administrator, or backend activation was introduced. [The audit report](../reports/operations/production-operations-observability-v1.json) separates current Production samples from dashboard capability.

## Boundary and model

The exact operations path is protected at the request boundary by middleware: it checks the existing Supabase cookie session with `auth.getUser()` and requires `app_metadata.operations_role=operations_admin`, returning HTTP 404 if configuration or authorization is absent. The server-rendered page rechecks that role. The health API independently checks a Bearer token with `auth.getUser()` and the same role. It returns only sanitized states and Boolean flag values. Missing auth configuration, missing/expired sessions, and missing role fail closed. The page is `noindex,nofollow`; `/admin/` and `/api/` are disallowed by robots and neither is in the public sitemap. No API key, token, raw environment dump, flag toggle, deployment trigger, or mutation control is exposed.

Source states are `AVAILABLE`, `STALE`, `DISABLED`, `ERROR`, `UNKNOWN`; service health states are `HEALTHY`, `DEGRADED`, `DISABLED`, `ERROR`, `UNKNOWN`. These describe operations only. They never indicate sea or navigation safety. The page shows six bounded HTTP route checks, existing RISA cache metadata, source flag states, 38 static Conditions profiles, Today Sea partial-rendering support, deployment metadata if Vercel supplies it, and limitations. Kakao SDK authorization is checked in the authenticated browser. Navigation HTTP 200 is explicitly **not** treated as MapLibre canvas or GPS proof. Release status is labeled as a dated historical audit, not a current live verdict.

## Current Production sample

At the bounded read-only check, Home, Sea, Navigation, Fishing Spots, Conditions, and Today Sea each returned HTTP 200 (roughly 1.0–1.6 seconds from the checker). RISA returned HTTP 200, 41 stations, cache freshness `fresh`, about 2.9 seconds, and latest raw source clock `2026-09-27T05:30:00`; NIFS does not document that clock's timezone. FEMO, KMA observation, KMA warning and KHOA navigation warning returned `SOURCE_DISABLED`; KMA forecast and KHOA tide returned `API_KEY_MISSING`. FEMO's last audited sample source clock is `2025-11-05 10:10`, historical reference only. This one sample does not establish an error rate or SLA. The Production deployment `dpl_3DC6NWh58BXQMBqvEXyx5dtZYJuu` was Ready, but CLI inspection did not expose its Git SHA. The dashboard displays `VERCEL_GIT_COMMIT_SHA` when present and otherwise says unknown.

## Collection and limits

An authorized manual refresh reads a per-instance 60-second snapshot. Six same-origin page checks have a four-second timeout, while RISA reuses its existing ten-minute upstream cache and in-flight sharing. The static Conditions read-model API is checked with an explicit species/month, without a new upstream request. Independent results keep an individual route or source failure from turning the whole snapshot into a 500. The current 5xx counter covers only these bounded checks; no persistent history, cross-instance deduplication, vendor integration, daemon, automatic polling, alert, source recovery, feature-flag change, or rollback was added. A future alerting design should define ownership, thresholds, retention, quota budgets, and incident response before implementation.

Current limits include absent Production Auth, unavailable authenticated Preview visual QA, unknown Kakao/MapLibre browser state until an operator can open the page, blocked real-device GPS/PWA QA, undocumented RISA time zone and provider quotas, FEMO's historical-only sample and undocumented salinity unit, and disabled KMA/KHOA sources. Production source flags and environments were not changed.

The final [Preview deployment](https://blue-marina-f1efva1z4-chiweon.vercel.app) passed the fail-closed and public-route smoke check: unauthenticated `/admin/operations` returned HTTP 404 with `noindex,nofollow`, the health endpoint returned 401 without a token and 503 `OPERATIONS_AUTH_UNAVAILABLE` with an invalid token, and Home and Today Sea remained HTTP 200. Authenticated dashboard data and 390px/1280px visual QA could not run without Auth configuration and an authorized operator. Production deployment was therefore not performed. The local and Preview builds succeeded, with a non-fatal Supabase SSR Edge package warning.

Supabase Auth patterns were checked against the [Supabase server-side client guidance](https://supabase.com/docs/guides/auth/server-side/creating-a-client) and [getUser reference](https://supabase.com/docs/reference/javascript/auth-getuser); no schema or role assignment is part of this work.
