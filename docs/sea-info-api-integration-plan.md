# Blue Marina 해양정보 API 연동 1차 설계

작성일: 2026-06-20  
대상 기능: `/sea-info`  
상태: 설계 문서. 실제 라우트, API 호출 코드, API 키, `.env.local`은 생성하지 않음.

## 1. 목표

Blue Marina에 조석, 만조/간조, 수온, 파고, 조류, 일출/일몰, 풍속/풍향, 기온, 강수, 해상예보를 통합해서 보여주는 해양정보 기능을 추가하기 전 구조를 정의한다.

1차 구현 목표는 사용자의 현재 위치를 기준으로 가까운 해양 관측소 또는 예보 지점을 찾고, 낚시와 해양레저 판단에 필요한 정보를 카드형 화면으로 제공하는 것이다.

## 2. API 후보

### 국립해양조사원 / 해양수산부 공공데이터

우선 검토 후보:

- 조석예보(고, 저조)
  - 제공 내용: 예보지점명, 예측일시, 위도/경도, 예측조위값, 고조/저조 구분
  - 활용 화면: 만조/간조, 조석표, 오늘의 물때 요약
  - 우선순위: 상

- 조석예보(시계열)
  - 제공 내용 후보: 시간대별 조위 예측
  - 활용 화면: 하루 조위 곡선, 출조 가능 시간대
  - 우선순위: 중

- 수온
  - 후보 출처: 국립해양조사원 신규 개방 데이터 또는 국립수산과학원/해양 관측 데이터
  - 활용 화면: 현재 수온, 어종별 참고 정보
  - 우선순위: 중

- 파고
  - 후보 출처: 해양관측부이 또는 기상청 해상예보
  - 활용 화면: 출조 위험도, 해상 상태
  - 우선순위: 상

- 조류
  - 후보 출처: 국립해양조사원 조류예보 또는 대체 국가중점데이터
  - 활용 화면: 조류 방향, 유속, 물흐름 참고
  - 우선순위: 중

- 일출/일몰
  - 후보 출처: 국립해양조사원 천문/해양 예보 계열 데이터 확인 필요
  - 활용 화면: 출항/입항 계획, 야간 주의 안내
  - 우선순위: 중

주의:
공공데이터포털에 국립해양조사원 OpenAPI 35종 제공중단 및 대체서비스 안내가 공지되어 있다. 조위, 파고, 수온, 조류 등 일부 기존 API는 폐기 목록에 포함되어 있으므로, 실제 구현 전 반드시 현재 활성 데이터와 대체 API를 다시 확인해야 한다.

### 기상청 API

우선 검토 후보:

- 기상청 API허브 예특보
  - 제공 내용: 초단기, 단기, 중기예보, 기온, 바람, 강수량, 기상특보
  - 활용 화면: 풍속, 풍향, 기온, 강수, 특보
  - 우선순위: 상

- 기상청 단기예보
  - 제공 내용 후보: 3시간 기온, 풍향, 풍속, 하늘상태, 강수형태, 강수확률, 강수량, 습도, 파고 등
  - 활용 화면: 오늘/내일 출조 참고
  - 우선순위: 상

- 기상청 중기예보
  - 제공 내용 후보: 향후 11일까지의 기상전망, 육상/해상 날씨, 최고/최저기온, 파고
  - 활용 화면: 주간 해양레저 계획
  - 우선순위: 중

## 3. 필요한 환경변수 설계

실제 키는 입력하지 않는다.

```env
KHOA_API_KEY=
KMA_API_KEY=
```

추후 분리 가능 후보:

```env
KHOA_TIDE_API_KEY=
KHOA_OCEAN_OBSERVATION_API_KEY=
KMA_FORECAST_API_KEY=
KMA_MARINE_FORECAST_API_KEY=
```

권장 정책:

- 서버 사이드 API 라우트에서만 키 사용
- 브라우저에 비공개 키 노출 금지
- `.env.local`은 Git에 포함하지 않음
- 배포 시 Vercel 환경변수에만 등록
- API 응답 캐싱 계층을 두어 호출량 제한 대응

## 4. 위치 기반 구조 설계

### 기본 흐름

1. 사용자가 `/sea-info` 진입
2. 브라우저 Geolocation API 권한 요청
3. 권한 허용 시 현재 위도/경도 획득
4. 관측소 목록에서 거리 계산
5. 가장 가까운 관측소 또는 예보 지점 선택
6. 조석/기상/해양 관측 API 조회
7. 카드형 정보 표시

### 권한 거부 시 fallback

1. 지역 선택 UI 표시
2. 사용자가 시/도, 항구, 대표 해역 선택
3. 해당 지역의 기본 관측소 또는 예보 지점 사용
4. 위치 권한 없이도 기본 해양정보 표시

### 거리 계산

관측소와 사용자 위치의 거리는 Haversine 공식을 사용한다.

```ts
type Coordinates = {
  lat: number;
  lng: number;
};
```

거리 계산 결과는 km 단위로 표시한다.

## 5. 관측소 데이터 구조 설계

파일 후보:

`src/data/marine-observatories.ts`

```ts
export type MarineObservatory = {
  id: string;
  name: string;
  type: "tide" | "ocean-buoy" | "weather-buoy" | "forecast-zone" | "sunrise-sunset";
  region: string;
  lat: number;
  lng: number;
  supportedData: Array<
    | "tide"
    | "high-low-tide"
    | "water-temperature"
    | "wave-height"
    | "current"
    | "sunrise-sunset"
    | "wind"
    | "precipitation"
    | "marine-forecast"
  >;
  source: "KHOA" | "KMA" | "NIFS" | "manual";
  sourceId?: string;
  note?: string;
};
```

초기 데이터 입력 원칙:

- 공식 자료로 확인된 관측소만 입력
- `lat`, `lng`는 공식 좌표 또는 검증된 좌표만 입력
- API별 지점 코드가 있으면 `sourceId`로 보관
- 동일 지점이 조석/수온/풍속 등 여러 데이터를 지원하면 `supportedData`에 배열로 기록
- 데이터가 불확실하면 `note`에 “공식 확인 필요” 표시

## 6. `/sea-info` 1차 화면 구성안

### Hero

- 제목: 해양정보
- 설명: 현재 위치 기반으로 조석, 날씨, 파고, 수온을 확인하는 공간

### 위치 카드

- 현재 위치
- 가까운 관측소
- 관측소까지 거리
- 위치 권한 상태

### 오늘의 바다 카드

- 만조/간조
- 풍속/풍향
- 파고
- 수온
- 일출/일몰

### 출조 참고 지수

단순 규칙 기반 1차:

- 풍속이 높으면 “주의”
- 파고가 높으면 “위험”
- 강수 확률이 높으면 “주의”
- 조석 변화가 큰 시간대는 “물때 변화 주의”
- 데이터가 부족하면 “공식 자료 확인 필요”

표시 예:

- 좋음
- 보통
- 주의
- 위험
- 데이터 부족

### 상세 카드

- 조석표
- 해상날씨
- 관측소 정보
- API 데이터 갱신 시간

## 7. fallback 구조

### 위치 권한 거부

- 지역 선택 화면 표시
- “현재 위치 권한 없이도 지역 기준 해양정보를 확인할 수 있습니다.” 문구 표시

### API 실패

- 해당 카드에 “데이터를 불러오지 못했습니다.” 표시
- 전체 화면 실패로 처리하지 않음
- 공식 사이트 확인 안내

### 데이터 없음

- “이 관측소에서는 해당 데이터가 제공되지 않습니다.” 표시
- 다른 가까운 관측소 추천 가능

### 호출량 제한

- 서버 캐시 적용
- 동일 지점/동일 날짜 데이터는 일정 시간 재사용

## 9. 구현 전 결정해야 할 사항

- KHOA는 공공데이터포털 API를 우선할지, KHOA 자체 서비스 또는 대체 국가중점데이터를 우선할지 결정
- 기상청은 API허브와 공공데이터포털 중 어느 발급/운영 경로를 사용할지 결정
- 관측소 좌표와 API 지점 코드를 어떤 출처에서 수집할지 결정
- 출조 참고 지수의 기준값을 공식 근거 기반으로 둘지, Blue Marina 내부 참고 지수로 표시할지 결정
- 위치정보 처리 문구를 개인정보처리방침에 반영할지 결정

- 공공데이터포털: 국립해양조사원 OpenAPI 35종 제공중단 및 대체서비스 안내

## 11. 1차 API 라우트 구현 상태

현재 구현된 서버 라우트:

- `/api/sea-info/tide`

입력 query:

- `stationId` 또는 `obsCode`
- `date` (`YYYY-MM-DD`)

현재 안전 응답 정책:

- `MISSING_STATION`: `stationId` 또는 `obsCode`가 없는 경우 400
- `MISSING_DATE`: `date`가 없는 경우 400
- `INVALID_DATE`: `date`가 `YYYY-MM-DD` 형식이 아닌 경우 400
- `API_KEY_MISSING`: 서버 환경변수 `KHOA_API_KEY`가 없는 경우 503
- `UPSTREAM_NOT_CONFIGURED`: 실제 KHOA endpoint가 아직 검증되지 않은 경우 501
- `UPSTREAM_ERROR`: 외부 API 호출 또는 응답 처리 실패 시 502

중요 원칙:

- `KHOA_API_KEY`는 서버 전용 환경변수다.
- `NEXT_PUBLIC_KHOA_API_KEY` 같은 클라이언트 공개 환경변수는 만들지 않는다.
- 실제 서비스키를 코드, 문서, `.env.local`, 커밋에 넣지 않는다.
- 클라이언트는 `/api/sea-info/tide` 내부 라우트만 호출한다.
- 실제 KHOA endpoint와 파라미터명은 공식 문서로 검증하기 전까지 임시 URL을 넣지 않는다.

## 13. 기상청 API 준비 계획

기상청 API는 다음 환경변수를 사용한다.

```env
KMA_API_KEY=
```

보안 원칙:

- `KMA_API_KEY`도 서버 라우트에서만 사용한다.
- 프론트엔드에 API 키를 노출하지 않는다.
- `NEXT_PUBLIC_KMA_API_KEY`는 사용하지 않는다.

향후 서버 라우트 후보:

- `/api/sea-info/weather`

제공 예정 데이터:

- 풍속
- 풍향
- 기온
- 강수
- 하늘상태
- 파고 또는 해상예보

KMA 라우트 fallback 정책:

- API 키 없음: “기상청 API 키 설정 후 이용 가능합니다.”
- 지점 코드 없음: “예보 지점 정보가 필요합니다.”
- API 실패: “기상 정보를 불러오지 못했습니다. 공식 사이트를 확인하세요.”
- 데이터 없음: “해당 지점에서 제공되는 기상 데이터가 없습니다.”

## 14. KHOA + KMA 통합 표시 구조

`/sea-info` 화면은 데이터를 출처별로 분리해서 호출하되, 사용자에게는 하나의 카드 묶음으로 보여준다.

권장 흐름:

1. 사용자가 지역 또는 현재 위치 기반 관측소를 선택한다.
2. 선택된 관측소가 `tide`를 지원하면 KHOA 조석 라우트를 호출한다.
3. 선택된 관측소가 `wind`, `wave`, `waterTemperature`를 지원하면 KMA 또는 별도 해양 관측 라우트를 호출한다.
4. 성공한 데이터만 카드에 표시한다.
5. 실패한 데이터는 카드 전체를 깨뜨리지 않고 “준비중” 또는 “불러오지 못함” 상태로 표시한다.

화면 fallback 문구:

- “현재 이 관측소에서는 해당 정보가 준비중입니다.”
- “공식 API 연결 후 표시됩니다.”
- “데이터를 불러오지 못했습니다. 잠시 후 다시 시도하거나 공식 사이트를 확인하세요.”

## 15. 현재 위치 기반 구조 준비

Geolocation API 사용 원칙:

- 사용자가 버튼을 클릭한 뒤에만 위치 권한을 요청한다.
- 페이지 진입 즉시 위치 권한을 요청하지 않는다.
- 위치 권한을 거부해도 `/sea-info` 화면은 계속 사용 가능해야 한다.

fallback 구조:

- 위치 권한 허용: 현재 위도/경도 획득
- 위치 권한 거부: 지역 선택 UI 표시
- 위치 획득 실패: 기본 지역 또는 수동 지역 선택으로 전환

거리 계산:

- 현재 위치와 `marine-observatories.ts`의 41개 관측소 좌표를 비교한다.
- `findNearestObservatory()`로 가장 가까운 관측소를 선택한다.
- 관측소가 지원하지 않는 데이터는 숨기거나 “준비중”으로 표시한다.

개인정보 원칙:

- 사용자의 현재 위치는 브라우저 안에서 가까운 관측소 계산에만 사용한다.
- 현재 위치를 서버에 저장하지 않는다.
- 현재 위치를 로그, 분석, localStorage에 저장하지 않는다.
- 위치 기반 기능을 사용할 때는 “현재 위치는 가까운 관측소 계산에만 사용됩니다.” 문구를 표시한다.
