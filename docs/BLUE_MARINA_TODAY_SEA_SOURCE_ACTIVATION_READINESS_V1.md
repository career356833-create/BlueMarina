# Blue Marina Today Sea Source Activation Readiness V1

Decision: `TODAY_SEA_SOURCE_ACTIVATION_HOLD`. The five sources are still disabled in Production. Vercel Preview and Production both lack all five sources' required credential names; the KMA warning and KHOA navigation-warning enable flags are also absent. This is a readiness audit, not an activation. No environment value, flag, deployment, database, or production feature was changed.

The baseline is `main` at `10d7dd200c60d91fc3d465cdfe8161700e947e99`. The public `/today-sea` page returned HTTP 200 while all five Production source routes returned source-level HTTP 503. The browser uses five independent API calls only when appropriate: KMA station metadata and the two warning feeds on load, observation only after exact station selection, forecast only after explicit numeric zone submission, and tide only after station/date selection. A source `DISABLED`, `ERROR`, `TIMEOUT`, or `STALE` state is confined to its card. `fetch` has an abort controller, but no cross-request in-flight deduplication. Server caches are per process, not distributed; cold concurrent requests can duplicate upstream traffic.

## Environment and bounded live evidence

`vercel env ls preview` and `vercel env ls production` were used to inspect **names and scopes only**. Neither scope contains `KMA_APIHUB_KEY`, `KMA_MARINE_STATION_API_KEY`, `KMA_MARINE_OBSERVATION_API_KEY`, `KMA_MARINE_WARNING_API_KEY`, `KHOA_API_KEY`, or `KHOA_NAVIGATION_WARNING_API_KEY`. `KMA_MARINE_WARNING_ENABLED` and `KHOA_NAVIGATION_WARNING_ENABLED` are absent, so they fail closed. The relevant names exist in local ignored environment files; values were never printed, copied, or stored in this audit. Local presence does not establish deployed authorization or quotas.

One bounded Production read per route returned: page 200; KMA forecast 503 `API_KEY_MISSING`; KMA station catalog and observations 503 `API_KEY_MISSING`; KMA warning 503 `SOURCE_DISABLED`; KHOA tide 503 `API_KEY_MISSING`; KHOA navigation warning 503 `SOURCE_DISABLED`. Each response is JSON except the page. Preview was not probed again because its credential-name audit already predicts the same disabled state. These HTTP statuses prove failure isolation, not upstream reliability.

Local bounded reads with existing local credentials returned KMA station catalog HTTP 200 / 76 stations, KMA observations HTTP 200 / 137 rows (latest `2026-09-27T00:00:00+09:00`), and KMA warnings HTTP 200 / zero current rows. The latest observation was about 22 minutes before audit time; the published source family has `:00/:30` production times. This is a recent sample, not a Production freshness claim. Zero warnings is a valid empty response, **not** evidence that the sea is safe. A representative KMA forecast request returned 502 `UPSTREAM_ERROR` on both bounded attempts. A KHOA tide request for `DT_0001` on 2026-09-27 returned 504 `UPSTREAM_TIMEOUT` after its 8-second boundary. No latest forecast or tide event could be verified now. KHOA navigation warnings were not called locally: a cold request may expand into paginated list requests and one or more detail calls per unique document; the prior audit observed 112 unique documents. Quota and latency should be reviewed before another live probe.

## Conditional candidates and Preview gate

Select at most two **conditional** candidates: **KMA observations**, then **KMA warnings**. Their local credentials are available and bounded local reads succeeded. Neither is authorized for Production until deployed keys, quotas, Preview behavior, source freshness, and failure isolation have been verified. The other three stay on hold. KMA forecast requires upstream error diagnosis, KHOA tide requires a successful current prediction and datum/timezone treatment, and KHOA navigation warnings require lifecycle and cold-request fan-out review.

1. Verify KMA observation station and data credentials and quotas outside the browser. Register both server-only names in **Preview**; deploy Preview; confirm station metadata and an exact selected station, raw `TM`, official units, recent sample age, stale/timeout behavior and `/today-sea` HTTP 200 with other cards unaffected.
2. Verify KMA warning credential and quota. Register its server-only key in **Preview**, then enable only `KMA_MARINE_WARNING_ENABLED` in Preview; deploy Preview; inspect current/history/zone calls, empty and non-empty responses, issue/effective/expected-end fields, lifecycle, and isolation. Zero warnings must never become a safety verdict.
3. For both, inspect per-instance cold request counts and simultaneous-request duplication, credential absence from client bundles/responses/logs, and page 200 during disabled/error/timeout/stale paths. Retain clear `관측`, `특보`, `예보`, `조석 예측`, and `항행 참고정보` labels.
4. A **separate** Production gate may follow only after Preview passes: production-scoped credential authorization and quota, official freshness check, bounded latency and volume, no key exposure, rollback plan, and explicit review. This audit changes neither Preview nor Production.

Server routes read non-`NEXT_PUBLIC_` keys. The Today Sea component calls only same-origin `/api/...` paths, with no direct browser upstream call or client key. The reviewed routes do not return authenticated upstream URLs. Audit output stores key names and status only. This is a static and bounded runtime inspection, not a full deployed-bundle or log-forensic proof.

No score, recommendation, nearest-station mapping, tide-plus-depth calculation, safe route, departure verdict, or aggregate risk rank is introduced. No Git staging, commit, or push was performed.
